# Glow Map 构造质量对比：ONVE vs. Li et al. ICCV 2015（+ 改进算法 GAR）

**结论先行（三方法）：**
1. 原始两方对比中，**Li et al. ICCV 2015 总体优于 ONVE**（详见下文）；
2. 后续任务中实现的 **GAR（Glow via APSF Refit）** 在合成基准上三项指标全胜
   （平均 PSNR 28.08，比 Li +6.3 dB），但在 4 张真实图的逐例目视检查中暴露了 3 个失效模式
   （详见 7.5 鲁棒性评估）。**修正后的推荐：通用场景仍用 Li 2015**（弱先验、失效渐进、行为可预测）；
   GAR 是"强物理假设换精度"的研究原型，仅适用于光源可见且饱和的受控条件，且需逐图目视验收。

**原始两方结论：在"构造更准确的 glow map"这一目标上，Li et al. ICCV 2015 的相对平滑度层分解总体更好** ——
在有真值的合成基准上平均 PSNR 高约 2 dB（21.77 vs 19.73）、MAE 更低，且速度快约 2000 倍（0.3 秒 vs 约 14 分钟/图，CPU）。
ONVE 的优势在于结构定位：多小光源、紧凑光晕场景下 SSIM 更高，梯度泄漏（场景纹理渗入 glow 图）显著更低，
但其 glow 幅值系统性低估。两者详细的适用场景见文末。

## 1. 对比对象

| | ONVE | Li et al. 2015 |
|---|---|---|
| 出处 | [WuWanyu98/ONVE](https://github.com/WuWanyu98/ONVE)（TCSVT 2025 / IJCAI 2023 官方代码） | [Nighttime Haze Removal with Glow and Multiple Light Colors](https://openaccess.thecvf.com/content_iccv_2015/papers/Li_Nighttime_Haze_Removal_ICCV_2015_paper.pdf)（ICCV 2015） |
| 范式 | 零样本深度先验（Double-DIP 类）：两个 skip 编解码网络分别生成光源层与背景层，一个 FCN 生成 15×15 APSF 卷积核；glow map = 光源层与该核的**三重卷积** | 经典优化：相对平滑度层分解。glow 层梯度短尾（对 `I−J` 的拉普拉斯二范数惩罚），场景层梯度长尾（稀疏），半二次分裂 + FFT 闭式求解 |
| 主要损失/先验 | VGG 感知重建 + 排斥损失（exclusion）+ TV 损失 + 灰度损失；需要亮度阈值生成的 bg/fg/light 三张 hint 图 | `min_J Σ‖∇J‖₀ + λ‖∇²(I−J)‖²`，约束 `0 ≤ J ≤ I`；β 逐轮翻倍的硬阈值组稀疏 |
| 可调参数 | 迭代数、weight（分离程度）、gamma、hint 阈值 | λ（glow 平滑度权重）、预平滑 σ |
| 每图耗时（256px, 4 核 CPU） | ~820 秒（2500 迭代） | ~0.3 秒 |

Li 2015 的实现按用户提供的参考实现（`glow_estimation.py`）与作者发布的 MATLAB 求解器（`layer_decom.m`）逐式对齐；
ONVE 使用官方仓库代码，仅做 CUDA→CPU 适配与离线 VGG16-bn 权重加载（权重为 torchvision 同源文件，经命名转换严格加载）。

## 2. 实验设置

- **合成基准（有真值）**：3 个场景（`data/synthetic/`），成像模型 `I = clip(J + G + cores)`，
  `G = APSF ⊛ (HDR 光源)`，APSF 用重尾广义高斯核逼近（σ∈[3.5, 9]，p∈[0.5, 0.7]），
  涵盖多暖光、单一大光晕、六个小光源三种布局。真值 glow 已知，可算 PSNR/SSIM/MAE。
- **真实图像（无真值）**：ONVE 仓库自带的 4 张夜景测试图，用无参考指标：
  - 平滑度（glow 图拉普拉斯绝对均值，APSF 卷积结果应平滑，越低越好）
  - 泄漏（glow 图梯度与输入非高光区梯度的 Pearson 相关，量化场景纹理渗入，越低越好）
  - 负残差（`I − G < 0` 的像素占比，glow 高估导致的过减，越低越好）
- **公平性**：两方法在完全相同的 256px 工作分辨率输入上运行。ONVE 用仓库默认 2500 迭代与默认损失权重；
  Li 的 λ 经合成集扫描（200–6000）验证参考实现默认值 λ=1562.5 已接近最优（见 `results/li_lambda_sweep.json`），未偏袒调参。

- **syn1/syn2**：Li 的光晕亮度、形状最接近真值；ONVE 的 glow 整体偏暗（幅值低估），这是它 PSNR/MAE 落后的主因。

- **DSC00983（真实街景）**：Li 的 glow 图能看到明显的车体和红灯轮廓（泄漏 0.190）；ONVE 的图是更抽象的光晕色块。
- **input_000009（栅栏后的强光）**：两者都出现栅栏竖条纹渗入，Li 更明显；这正是"不规则 glow"（遮挡产生非对称光晕）
  对两种平移不变 APSF 假设的共同挑战。

## 5. 结论与建议

**哪个能构造更好的 glow map？——分两种"好"：**

1. **幅值准确性/重建保真（多数去光晕用途的核心）：Li et al. 2015 胜。**
   PSNR 平均高 2 dB、MAE 更低、光晕亮度不低估，且 0.3 秒/图、单参数、行为可预测。
   如果 glow map 的用途是从输入中减除光晕（`J = I − G`）或做数据集标注，建议用 Li 2015。

2. **结构分离纯净度（glow 图不含场景纹理）：ONVE 胜。**
   排斥损失使泄漏指标接近 0，多小光源场景 SSIM 更高。如果 glow map 的用途是作为引导图
   （如 ONVE 自己的增强阶段用 gray map 引导 Retinex），或场景是论文主打的"不规则 glow"，ONVE 的可学习 APSF 核更有潜力
   ——但要接受幅值低估、DIP 噪声、约 2000 倍的耗时以及对 hint 质量的依赖。

**实验局限**（诚实起见）：ONVE 在 CPU 上以 256px/2500 迭代运行官方默认超参，未做每图调参，GPU 上更高分辨率/更多迭代可能改善；
合成基准的 glow 是平移不变 APSF（"规则"glow），这与 Li 的先验假设一致，也与 ONVE 的单核卷积模型一致，
但未覆盖 ONVE 论文主打的强不规则 glow 场景；真实图像结论基于无参考指标与目视检查。

## 7. 改进算法：GAR（Glow via APSF Refit）

### 7.1 候选算法检索

以"比 Li 2015 更好的 glow 估计"为目标检索到的主要候选：

| 候选 | 核心思想 | 本环境可测性 |
|---|---|---|
| Jin et al., ACMMM 2023（[nighttime_dehaze](https://github.com/jinyeying/nighttime_dehaze)） | Guided APSF + 梯度自适应卷积，Li 2015 的直接后继 | ✗ 预训练权重仅 Dropbox/百度网盘，网络策略封锁 |
| Jin et al., ICCV 2021（[night-enhancement](https://github.com/jinyeying/night-enhancement)） | 无监督层分解 + 光效应抑制网络 | ✗ 同上 |
| ONVE（已测） | 零样本深度先验 + 可学习 APSF 核 | ✓ 已在第 3 节对比，弱于 Li |
| 经典改进方向：物理约束 APSF 拟合 | 把 glow 显式约束为"点光源 ⊛ APSF 核"的物理形式 | ✓ **实现为 GAR 并验证** |

### 7.2 GAR 算法（`gar.py`）

关键观察：Li 2015 的失误模式是**形状偏差**（把 glow 摊得过开）与**低频结构泄漏**；ONVE 的失误模式是**幅值低估**。
两者都没有利用 glow 最强的物理约束——它是点光源与单一 APSF 核的卷积。GAR 直接拟合这一物理模型：

1. **光源核检测与色度校正**：输入中高亮像素（max-channel ≥ 0.9）构成彩色点光源图——阈值刻意低于完全饱和，
   使强彩色光源（如蓝色路牌）也被计入；此外，饱和会使核内颜色偏白（红灯核实测 RGB≈(0.96,0.49,0.38)，
   会渲染出灰色光晕——由用户在 DSC01015 红灯上发现），因此每个光源的色度改从其核外 1–8px
   的未饱和光晕环中值颜色估计，核重新着色为"环色度 × 核亮度"；
2. **双尺度非对称下包络 APSF 拟合**：真实 APSF 是"尖峰 + 重尾"，单核拟合会二选一
   （宽环境光罩会抹掉点光源的紧凑亮晕——由用户在 DSC01173 路灯上发现）。
   GAR 先在近核区域（≤25px）拟合窄核（σ∈[0.5,12]，管点光源亮晕），再在其残差上拟合宽核
   （σ∈[8,100]，管环境光罩），各配逐通道幅值。损失为**非对称包络损失**：
   模型超过输入罚 8 倍、低于输入罚 1 倍（光晕是输入亮度的下包络：`G ≤ J+G = I`）。
   这一步完全绕开 Li 分解的形状偏差，直接从数据恢复核参数；
3. **环境光床**：Li 分解残差的大尺度低通（σ=25）补足点光源模型无法表达的环境色罩，与拟合项取 max 融合；
4. **smooth-min 包络**：以输入的形态学闭运算（21px 椭圆核 + σ=4 高斯）为上界 U，
   `G ← G/(1+(G/U)⁴)^{1/4}` ——低于上界的值几乎不衰减（保住弱彩色光晕），逼近上界时平滑压制，
   避免硬截断把场景暗纹理反印进 glow 图。此设计经真实图 DSC01173 的反馈迭代确定：
   早期指数压缩版本会把蓝色路牌的光晕压没。

### 7.3 GAR 结果

合成集（vs 真值 glow）：

| 场景 | PSNR↑ ONVE / Li / **GAR** | SSIM↑ ONVE / Li / **GAR** | MAE↓ ONVE / Li / **GAR** |
|---|---|---|---|
| syn1 | 16.59 / 19.06 / **27.50** | 0.789 / 0.823 / **0.911** | 0.062 / 0.046 / **0.023** |
| syn2 | 24.86 / 27.67 / **30.99** | 0.693 / 0.679 / **0.707** | 0.031 / 0.033 / **0.023** |
| syn3 | 17.72 / 18.60 / **25.75** | 0.612 / 0.533 / **0.621** | 0.049 / 0.055 / **0.033** |
| **平均** | 19.73 / 21.77 / **28.08** | 0.698 / 0.679 / **0.746** | 0.047 / 0.045 / **0.026** |

三项指标、三个场景全胜。两个佐证：

- **梯度统计正确性**：无参考"泄漏"指标下 GAR 为 0.37/0.44/0.66，而真值 glow 自身为 0.36/0.41/0.67
  ——几乎重合，说明 GAR 的 glow 梯度就是真实 glow 的梯度（该指标对锐利而准确的光晕会"误报"，
  这也解释了为何不能单看泄漏指标评价方法）；
- **定性**：syn3 中六个紧凑光晕全部准确恢复（ONVE 几乎丢失、Li 摊开且渗入杯子轮廓）；
  真实图 input_000009 中 GAR 是唯一不把栅栏条纹渗入 glow 图的方法。

设计迭代记录：早期版本用指数压缩 `U(1−e^{−G/U})`（平均 25.66）或硬约束 `min(G,U)`（27.29 但有纹理反印）；
逐光源独立幅值的尝试在真实图上退化为"输入的模糊版"（自由度过大顶满包络）被放弃；
此后按用户反馈三轮迭代：DSC01173 蓝色光晕丢失 → 阈值 0.9 + smooth-min（27.54）；
DSC01173 路灯点光源无可见亮晕（单核被宽光罩拉平）→ 双尺度窄+宽核混合（27.95）；
DSC01015 红灯光晕被渲染成灰色（饱和核偏白 × 蓝白主导的全局增益）→ 光晕环色度校正（**28.08**，最终版）。

局限：GAR 假设单一平移不变 APSF 与可见的饱和光源核——多种差异极大的光源混合、
或光源在画面外/完全被遮挡时会退化（此时环境光床项兜底，行为回落到接近 Li）；
合成基准与 GAR 共享"APSF 卷积"这一生成假设，对 GAR 有利，真实场景优势以无参考指标与目视为准。

### 7.3.5 继续检索：两个失败的经典候选与深度学习线的穷尽（阴性结果）

按"继续搜索和尝试"的要求追加了一轮检索与实验：

**深度学习线（穷尽确认）**：系统性尝试了获取权重的全部可达渠道——官方下载源（download.pytorch.org）、
HuggingFace、Dropbox/百度网盘（jinyeying 两个仓库的权重托管处）、仓库内提交的权重文件
（nighttime_dehaze 仓库中只有 `.pt.txt` 占位符）、README 中的 GitHub release 链接、
release 页面枚举（HTML 页面被代理拦截）。除 EDN 的 VGG16-bn（已用于 ONVE）外无一可达。
结论：在本环境网络策略下，ACMMM 2023 / ICCV 2021 等学习方法无法实测。

**经典改进线（两个候选均落败）**，实现见 `li_variants.py`：

| 候选 | 合成集 PSNR/SSIM/MAE | 真实图泄漏 (DSC01173/DSC01015) | 结论 |
|---|---|---|---|
| Li 基线 | 21.77 / 0.679 / 0.0449 | 0.158 / 0.150 | — |
| A. Li + WLS 精修（TIP 2020 后处理的彩色适配） | 21.69 / 0.651 / 0.0461 | 0.297 / 0.193 | ✗ 全面更差：WLS 的边缘保持特性把场景层的边缘保进了 glow 图（原论文用于灰度海雾，不适用彩色 glow） |
| B. 多尺度 Li 融合（全分辨率 max 半分辨率） | 21.25 / 0.648 / 0.0488 | — | ✗ max 融合系统性高估 |

这轮阴性结果强化了 7.5 节的判断：**Li 2015 在"无检测环节的经典方法"中处于局部最优**，
想鲁棒地超过它大概率需要学习到的先验（即那些权重不可达的深度方法）——
简单的后处理和多尺度组合都不行，而绕开其形状偏差的强物理假设路线（GAR）以鲁棒性为代价。

### 7.4 三方法总结

| | 幅值准确性 | 结构纯净度 | 鲁棒性 | 速度 | 依赖 |
|---|---|---|---|---|---|
| ONVE | ✗ 系统性低估 | ✓✓ 泄漏近零 | ✗ 依赖 hint 质量与调参 | ✗ ~14 min/图 (CPU) | hints、VGG 权重 |
| Li 2015 | ✓ | ✗ 低频泄漏 | **✓✓ 弱先验、失效渐进** | ✓✓ ~0.3 s | 单参数 λ |
| GAR | ✓✓（假设成立时） | ✓ | **✗ 强假设、失效面多** | ✓ ~7 s | 可见饱和光源核 + 多个手调超参 |

### 7.5 鲁棒性评估（诚实结论）

4 张真实图的逐例目视检查（用户执行）先后暴露 3 个失效模式：
DSC01173 蓝色光晕丢失（核阈值过高 + 包络压缩过度）、DSC01173 点光源亮晕被拉平（单核无法兼顾尖峰与宽尾）、
DSC01015 红灯光晕变灰（饱和核色度偏白 × 全局增益）。每处修复都引入了新的手调超参
（0.9 阈值、smooth-min k=4、21px 闭运算、双核 σ 区间、1–8px 色度环），
整条流水线是在 3 个合成场景 + 4 张真实图上调出来的——**真实图失败率 3/4，没有资格宣称鲁棒**。

这不是偶然而是结构性的：GAR 的合成集高分正来自其强物理假设（可见饱和光源 ⊛ 平移不变 APSF），
假设不成立（光源遮挡/画面外/不饱和、混合核、彩色环境光）就系统性退化。
Li 2015 只假设"glow 平滑"这一条弱先验，从不出彩但也从不灾难性出错。

**修正后的选型建议**：
- 通用/生产环境（图像多样不可控）：**Li 2015**。
- 受控条件（光源可见且饱和，如数据集合成/标注）且能逐图目视验收：GAR 的真值精度优势才可兑现。
- 真正"鲁棒且超过 Li"的候选是大数据训练的学习方法（ACMMM 2023 guided APSF，本环境权重不可达未能验证），
  或"Li 打底 + 检测置信时叠加物理拟合"的混合策略——均留待有权重/有大规模真实基准时验证。
  严格的结论需要几十上百张真实图上的失败率统计，而非小样本合成 PSNR。

## 8. 复现
